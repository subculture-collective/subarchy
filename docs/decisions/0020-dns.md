# ADR 0020: DNS and name resolution

Decision map item S3. Accepted 2026-11-06.

## Decision

All lookups go through **systemd-resolved**'s stub resolver. Each
NetworkManager connection carries a **DNS trust** setting:

| Trust | Applies to | DNS servers | Encryption |
|---|---|---|---|
| **Untrusted** (default) | Every newly joined network | The network's DNS is ignored; the chosen provider is used, **Quad9** by default (`9.9.9.9#dns.quad9.net`, `2620:fe::9#dns.quad9.net`) | Strict DNS-over-TLS; lookups fail rather than fall back to plaintext |
| **Trusted** | Networks the user marks, such as home | The network's DNS, or home DNS servers the user sets (on the owner's LAN: `10.0.0.200`, `10.0.0.57`) | Strict DNS-over-TLS when the server has a TLS name configured; otherwise plaintext on that network |

Also:

- **Captive portals**: when NetworkManager reports a portal on an untrusted
  network, the network's DNS is allowed for the login only, then the
  untrusted policy returns. The sign-in page opens in its own window and a
  Tailscale exit node is paused until the network is online, as Omarchy's
  `omarchy network captive portal` does ([[0058-tailscale|ADR 0058]]).
- **VPN and Tailscale**: their DNS stays scoped to their own links and routing
  domains, so MagicDNS and VPN split DNS keep working.
- **Local names**: Avahi answers `.local` (mDNS); resolved's own mDNS and
  LLMNR stay off.
- Users can change the provider and mark networks trusted or untrusted from
  the network panel and the CLI.

## Options considered

| Option | Why not chosen |
|---|---|
| Encrypted everywhere with home split DNS | Would bypass the home resolver's filtering for public names. |
| Opportunistic encryption everywhere | Plaintext on almost every public network. |
| Mullvad, Cloudflare, or own resolver only as default | Quad9 is non-profit, blocks malware domains and is already resolved's fallback on `sputnik`. |

## Evidence

On 2026-11-06, `sputnik`'s Wi-Fi link used `10.0.0.200` and `10.0.0.57` from
DHCP with DNS-over-TLS off. Neither server accepted connections on port 853.

## Consequences

- The owner's home DNS is plaintext on the LAN until DNS-over-TLS is enabled
  on Almaz. That is a homelab change, outside this repository; once done, the
  home connection gets the server's TLS name and becomes strict.
- Implementation: NetworkManager per-connection settings
  (`ipv4/ipv6.ignore-auto-dns`, `ipv4/ipv6.dns` with `#tls-name`,
  `connection.dns-over-tls`), a dispatcher or small daemon to apply the trust
  policy and the captive-portal exception, and resolved's global
  `DNSOverTLS=` setting. Verify each option name against the shipped
  NetworkManager and systemd versions.
- Strict mode means a blocked port 853 on a hostile network breaks DNS there;
  the panel must say so and offer a one-time trusted override.
- Omarchy enables resolved (`install/config/enable-services.sh`) but has no
  DNS policy to borrow; the trust layer is new work.

## Progress

- 2026-11-07: the untrusted default is in place: NetworkManager hands DNS to
  systemd-resolved (`/usr/lib/NetworkManager/conf.d/50-subarchy-dns.conf`),
  which sends every lookup (`Domains=~.`) to Quad9 over strict DNS-over-TLS
  (`/usr/lib/systemd/resolved.conf.d/50-subarchy.conf`); mDNS and LLMNR are
  off in resolved and Avahi answers `.local`. The VM test resolves over
  DoT. Not yet: per-network trust, captive portals, the provider setting.
